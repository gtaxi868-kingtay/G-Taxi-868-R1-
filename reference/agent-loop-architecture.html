Agent Loop Architecture

The 4-Phase Loop

 DISCOVERY → DECISION → FIX → VERIFY → (repeat)
 (auto)      (agent+human) (coder+human) (auto)

Glossary

Agent Preset
A config that bundles an agent persona, tools, memory file, and instructions. Created via jarvis init --preset <name>. Each audit type gets its own preset.
Sub-Agent
A specialized agent focused on one domain (DB audit, frontend audit, gap scan). Each sub-agent is a separate preset with its own prompt and tools. Can be run independently or orchestrated.
Strategy Agent
A sub-agent with a decision layer: check code → check web → ask human. Uses web_search tool for docs lookup and writes questions to a queue when stuck. Prevents false assumptions.
Skill
A reusable capability (Python script, shell script, prompt template) stored in ~/.openjarvis/skills/. Agents can invoke skills as tools. Reference: OpenJarvis Skills docs.
Memory File
A markdown file (MEMORY.md) that persists information between agent sessions. The agent reads it on start and can update it. Used to track known issues, architecture decisions, and audit history.
Discovery Phase
Automated checks: run tsc --noEmit, grep for patterns, query Supabase, read AGENTS.md. All sub-agents run in parallel. Output: a list of findings with evidence.
Decision Phase
Each finding is classified: Confirmed (clear evidence), Uncertain (needs more context), Unknown (cannot determine). Unknowns generate questions for the human.
Fix Phase
Findings routed to a coding agent (or human). Simple fixes auto-applied. Complex changes written by the coding agent. Each fix tagged with the finding ID for traceability.
Verify Phase
Re-run the same discovery checks. Confirm the finding is resolved. tsc --noEmit must pass. Update AGENTS.md session history to record the fix.
Coding Agent
The agent actually writing code (me, in the current session). Separate from Jarvis. Jarvis discovers and reports; the coding agent implements. Findings can be dropped as files or fed via API.
Question Queue
A directory (~/.openjarvis/questions/) where Jarvis writes pending questions. Each question file includes: finding context, what was checked, what's unknown, suggested answers. The user answers when convenient.
Runbook
A prompt template that tells an agent how to execute a specific operational task (deploy, rollback, check health). Stored as a skill. Can be triggered manually or on schedule.

Tool Connectivity

 Jarvis Engine ──┬── Ollama (local inference, privacy)
                 ├── shell_exec (supabase CLI, gh CLI, tsc, grep)
                 ├── web_search (API docs, error lookup)
                 ├── file_read/write (codebase access)
                 └── code_interpreter (Python scripts for analysis)

No plugin system needed — every tool is either built-in (Ollama, web_search) or accessed via shell commands you already have installed.

Key Commands

jarvis                          Start chat (default: chat-simple preset)
jarvis init --preset <name>     Create a new agent preset
jarvis ask "prompt"             Run a one-shot query against the default agent
jarvis model pull <name>        Download a model via Ollama
jarvis doctor                   Check installation health
jarvis skill install <path>     Install a skill from file
jarvis memory index <dir>       Index a directory for the agent to search
