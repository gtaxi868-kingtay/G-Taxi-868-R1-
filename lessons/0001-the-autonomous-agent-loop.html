You're building G-Taxi (72K lines, 7 apps, 23 edge functions). Every audit finds new gaps because the surface area is too large. You need an automated system that continuously monitors, audits, and reports — so you only involve your coding agent for actual fixes, not for discovery.

What Are "Strategy Agents"?

You asked about strategy agents that ask questions when they can't source info. Here's how that works:

🧠 Strategy Agent = an auditor that can decide what to do when it's unsure

A normal auditor just runs checks and reports. A strategy agent has a decision layer:

  1. Check code — grep, read files, run typecheck
  2. Check web — search docs (Supabase, Stripe, Amadeus) for reference
  3. If still unsure → ask the human — write a clear question with context
  4. Await answer — wait for your input before completing the report

This prevents the agent from making false assumptions or silently skipping issues it doesn't understand.

Example: Gap Scanner Strategy Agent Flow

Reads AGENTS.md "Genuine Remaining Gaps" section
Picks first gap: "SUPABASE EDGE FUNCTION SECRETS NOT CONFIGURED"
Checks source: greps for Deno.env.get("STRIPE_SECRET_KEY") in every edge function
Found uses? Yes — confirms gap is real
Checks: can I auto-fix this? No — requires dashboard config → tags as DASHBOARD
Moves to next gap. For anything unclear, checks web for API docs. If still unclear → writes question.

The Interface — What You See

You asked about the TikTok-style Jarvis interface. There are two paths:

🖥️ Path A: Web Dashboard (recommended)

OpenJarvis ships with a desktop app (download .dmg from GitHub Releases). It gives you:

  • A chat interface with your Jarvis agent
  • Activity log showing what auditors found
  • Question queue — unanswered questions Jarvis needs your input on
  • Workflow triggers — buttons to run audits on demand
📟 Path B: CLI + Terminal Notifications

If you prefer terminal:

  • jarvis ask "audit the payment flow" — runs the audit synchronously
  • Results printed to stdout as structured report
  • Jarvis writes questions to a file (~/.openjarvis/questions/) and pings you via terminal-notifier

You said you want all your tools connected. Here's the architecture:

       │           │           │           │
       ▼           ▼           ▼           ▼

  for privacy   + reviews  + RLS check  access + edits

The key insight: Jarvis doesn't need its own interface to everything. It uses your existing CLI tools (supabase, gh, tsc, grep) via the shell_exec tool. You don't need to install new integrations — just give Jarvis permission to run these commands.
